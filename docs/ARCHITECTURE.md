# Nava — Architecture

Nava (نوا) is an **offline, CPU-only Persian speech platform**. It is split into two
isolated FastAPI services — speech-to-text (STT) and text-to-speech (TTS) — plus a
small Python SDK. Everything runs on-premises: no external API calls, no telemetry,
models are mounted read-only from disk.

---

## 1. System overview

```
                         Host machine (localhost only)
                                       │
              ┌────────────────────────┴────────────────────────┐
              │                 docker compose                  │
              │                                                 │
              │   ┌──────────────────────┐  ┌──────────────────────┐
              │   │  nava-stt   : 8001   │  │  nava-tts   : 8002   │
              │   │  soft quota "cpus"   │  │  soft quota "cpus"   │
              │   │  optional cpuset     │  │  optional cpuset     │
              │   │  faster-whisper v3   │  │  G2P + 3 TTS engines │
              │   └──────────┬───────────┘  └──────────┬───────────┘
              │              └───────────┬─────────────┘
              │                bridge network (internal)
              └──────────────────────────┬────────────────────────┘
                                         │
                            ./models volume (read-only)
```

Resource sizing is **fully env-driven** (`.env`, generated by
`scripts/configure_infra.sh`): soft CPU quotas (`cpus:`) by default so any
machine works out of the box, with optional hard pinning (`cpuset`) and memory
limits for dedicated hosts. Key properties:

| Property | How it is achieved |
|---|---|
| Offline operation | `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, models loaded from disk |
| CPU governance | `cpus` quotas + optional `cpuset`; `OMP/MKL/OPENBLAS_NUM_THREADS` capped per service |
| Network isolation | `internal: true` bridge network (no egress); ports published only on `127.0.0.1` |
| Immutability | Models mounted `:ro`; containers are stateless |
| Fail-fast sizing | Oversized STT uploads rejected with `413` (Content-Length + streaming byte counter) |

## 2. Components

### 2.1 `nava-stt` — Speech-to-Text service

**Stack**: FastAPI + uvicorn (uvloop) + `faster-whisper` 1.1.1 (CTranslate2 backend).

Module layout:

- `app/settings.py` — env-driven `Settings` (workers, OMP threads, compute type, limits)
- `app/bodylimit.py` — stream-safe request-body limiting (pure stdlib, unit-tested)
- `app/main.py` — FastAPI app, engine, endpoints

- **Model**: Whisper `large-v3` on CPU, default `compute_type=int8`
  (~2–3× faster than `float32`, ~1.5 GB lighter; `float32` available for
  accuracy-critical nodes via `WHISPER_COMPUTE_TYPE`).
- **Language**: locked to `fa`; a Persian `initial_prompt` requests standard
  spelling, ZWNJ and punctuation. Optional `hotwords` bias recognition.
- **VAD**: Silero filter (`min_silence_duration_ms=400`, `speech_pad_ms=200`).
- **Decoding**: `beam_size=5`, `condition_on_previous_text=False`.

**Request handling**

```
POST /api/v1/transcriptions (octet-stream)
   ├─ Content-Length > limit?  → 413 immediately (nothing buffered)
   ├─ stream chunks, byte counter  → 413 mid-stream if exceeded
   ├─ size / alignment / min-length guards → 422
   └─ ThreadPoolExecutor(max_workers=stt_workers)
        └─ WhisperModel(cpu_threads=stt_omp_threads, num_workers=stt_workers)
```

The executor pool size **matches** `WhisperModel.num_workers`, so N parallel
requests actually run in parallel inside CTranslate2 instead of queuing on a
single model worker.

**WebSocket** `/ws/stt`: optional JSON config frame(s) first, binary frames
accumulate (per-frame *and* cumulative limit checks, close `1009` on overflow),
`{"action":"eos"}` triggers transcription; the connection is reusable. The SDK
sends audio as ≤1 MB frames, so the 15-minute limit works over WS too.

### 2.2 `nava-tts` — Text-to-Speech service

**Stack**: FastAPI + uvicorn + PyTorch CPU, `transformers` (T5 G2P),
`piper-tts` 1.3 (ONNX), `pocket-tts` Persian fork.

Module layout:

- `app/settings.py` — env-driven `Settings` (workers, threads, text limit, lexicon path)
- `app/textpipe.py` — Persian text pipeline (pure stdlib, unit-tested)
- `app/main.py` — engines, pipeline orchestration, endpoints

**Text pipeline** (`app/textpipe.py`, no heavy imports):

```
raw text
   │  normalize()               Arabic→Persian folding, ZWNJ→space, strip unsupported
   │  apply_surface_lexicon()   optional literal overrides (colloquial → standard)
   ▼
   ├─ pocket : chunk_pocket() (≤12 words/sentence)
   │           → G2P.run() (T5, beam=5, lru_cache 4096)     ┐ pipelined via
   │           → apply_phoneme_overrides()                   │ asyncio.Queue(2)
   │           → fit_token_budget(≤16 tokens per piece)      ┘
   │           → Pocket engine (stream decoder, silence/runaway guards)
   └─ mana   : split_sentences()
     piper     → Piper ONNX directly (own phonemization; NO neural G2P call)
   ▼
PCM chunks (s16le) joined with 150 ms silence, streamed to the client
```

**Engines**

| Engine | Type | Voice selection | Speed | G2P |
|---|---|---|---|---|
| `pocket` | pocket-tts flow-matching | any `.wav` prompt in `models/voices/` | not supported (422) | neural T5 G2P |
| `mana` | Piper ONNX | fixed voice | 0.5–2.0 | internal to Piper |
| `piper` | Piper ONNX | fixed voice | 0.5–2.0 | internal to Piper |

**Concurrency model**

- Single uvicorn worker; every model call is dispatched to a
  `ThreadPoolExecutor` (`NAVA_TTS_WORKERS`, default 2) — the event loop never
  touches inference.
- Each engine is serialized by an `asyncio.Lock` (the streaming decoders are
  not thread-safe); G2P has its own `threading.Lock` + 4096-entry `lru_cache`.
- **Pocket is pipelined** (producer–consumer, `asyncio.Queue(maxsize=2)`):
  chunk *N+1* phonemization (G2P executor thread) overlaps chunk *N* audio
  synthesis, so after the first chunk the engine never idles waiting on G2P.
  Engine/producer failures are forwarded through the queue; the producer task
  is always cancelled when the stream ends or the client disconnects.
- **Error semantics**: the REST endpoint synthesizes the *first* chunk before
  the response starts, so input problems surface as real `422`/`503` statuses
  instead of `200` with an empty stream. Late chunk failures (rare, e.g. a
  pathological single word over the token budget) still abort mid-stream.
- **Lexicon** (optional): `models/lexicon.json` (path via `NAVA_LEXICON_PATH`):

```json
{
  "surface":  {"می خوام": "می خواهم"},
  "phonemes": {"@": "?"}
}
```

  Surface overrides apply to all engines before splitting; phoneme overrides
  rewrite G2P output tokens (pocket only).

### 2.3 `nava_sdk` — Python client

- `NavaClient` — synchronous REST (httpx, one pooled client for both services).
- `AsyncNavaClient` — async REST + WebSockets: `transcribe_ws()` sends PCM in
  ≤1 MB frames (avoids per-frame size limits), `stream_speech_ws()` yields PCM
  chunks as they are produced. Connection-closed errors are mapped to
  `NavaServiceError`.

## 4. Deployment topology & infrastructure profiles

`docker-compose.yml` reads everything from the environment (defaults are safe
on any machine):

| Knob | Default | Meaning |
|---|---|---|
| `WHISPER_COMPUTE_TYPE` | `int8` | `int8` \| `int8_float32` \| `float32` |
| `STT_WORKERS` / `TTS_WORKERS` | `2` | inference thread pool (= Whisper `num_workers` for STT) |
| `STT_OMP_THREADS` / `TTS_OMP_THREADS` | `4` | BLAS/CTranslate2/torch threads |
| `STT_CPUS` / `TTS_CPUS` | `2.0` | soft CPU quota (`cpus:`) — works everywhere |
| `STT_CPUSET` / `TTS_CPUSET` | *(empty)* | hard core pinning; empty = disabled |
| `STT_MEM` / `TTS_MEM` | `8g` | container memory limits |

`scripts/configure_infra.sh [low|medium|high|auto]` detects the host
(`nproc` / `hw.ncpu`, `/proc/meminfo` / `hw.memsize`) and writes a tuned `.env`:

| Profile | Target | Compute | Workers | OMP | Pinning |
|---|---|---|---|---|---|
| `low` | 2–4 cores, 8 GB (edge/laptop/VPS) | int8 | 1 | 2 | none |
| `medium` | 8 cores, 16 GB (standard server) | int8 | 2 | 4 | halves (e.g. 0-3 / 4-7) |
| `high` | 16–32+ cores, 32 GB+ (accuracy node) | float32 | 4 | 8 | halves |
| `auto` | *(default)* picks by detected cores/RAM, clamping OMP threads to the granted cores | | | | |

Both containers have healthchecks (`/healthz` via urllib, generous
`start_period` for model loading).

## 5. Performance profile

- **STT**: `int8` large-v3 at `STT_WORKERS=N` gives N truly concurrent
  transcriptions; latency per request scales with `STT_OMP_THREADS` (capped to
  the granted cores). Requests above the audio limit are rejected in O(1) via
  Content-Length instead of buffering tens of MB.
- **TTS**: `mana`/`piper` skip neural G2P entirely (previously G2P ran and its
  output was discarded — pure waste). `pocket` overlaps G2P with synthesis
  (queue depth 2), so steady-state latency ≈ max(G2P, synthesis) per chunk
  instead of their sum; repeated sentences hit the G2P cache.
- **WebSocket**: the SDK's ≤1 MB framing plus `--ws-max-size 32000000` on the
  servers keeps the 15-minute STT limit reachable over WS.

## 6. Security posture

- Localhost-only port publishing; internal (no-egress) Docker network.
- Fully offline inference; read-only model volume.
- `voice_prompt` validated with `^[A-Za-z0-9_-]+$` **and** resolved-path check
  inside `models/voices/` (double path-traversal guard).
- Oversized request bodies rejected before buffering (memory-exhaustion guard).
- No authentication layer — by design for local/embedded use. Do **not** expose
  the ports beyond localhost without adding auth and rate limits.

## 7. Testing

`tests/` (pytest + pytest-asyncio):

- `unit/` — text pipeline (normalisation, ≤12-word chunking, ≤16-token budget
  fitting, lexicon overrides), stream-safe 413 limiting, settings env
  precedence, SDK helpers incl. chunked WS send (runs anywhere, no models).
- `integration/` — health, REST STT/TTS (incl. regressions for every fixed
  bug: 413 oversize, 422 empty text, 422 pocket+speed), raw WebSocket framing
  protocol, SDK round trips. Auto-skip when services are unreachable.

---

## 8. Known limitations

1. A pocket chunk whose *single word* alone exceeds the 16-token budget still
   fails mid-stream (multi-word chunks are always split to fit).
2. `voice_prompt` applies only to `pocket`; `mana`/`piper` are fixed voices.
3. No authentication — local/embedded use only by design.
4. G2P strips `؟`/`?` before generation, so pocket question intonation is
   approximate.
